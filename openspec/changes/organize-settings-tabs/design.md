## Context

当前 `SettingsWindow` 使用单个 `ScrollViewer` 承载所有设置内容，窗口高度固定为 720，设置项依次包含通用、窗口位置、位置预设、硬件采集、温度上限、颜色阈值和 LED 灯效。保存逻辑集中在 `SaveSettings()`，位置预设的新增、删除、排序和跳转由现有事件处理器即时处理。项目仓库为 `https://github.com/ChenDaqian/MagicCenterHub`，作者主页为 `https://github.com/Chendaqian`。

本变更主要调整 WPF 设置窗口的信息架构，并增加一个只读的版本与更新检查区域。配置模型、JSON 持久化、输入校验规则和主窗口回调均属于既有约束，不能因布局调整而改变。

## Goals / Non-Goals

**Goals:**

- 使用左侧标签页降低单页纵向长度和查找成本。
- 按用户任务将现有控件分为五个稳定分组：通用、窗口位置、硬件监控、LED 灯效、关于。
- 保持现有控件名称、事件处理和保存语义，确保跨标签页编辑后仍能一次应用或保存全部设置。
- 让每个标签页内容在窗口内独立滚动，底部操作区和状态文本保持固定可见。
- 在关于页展示当前版本、项目 Release 链接、作者主页、技术栈和开源组件，并支持手动检查更新。

**Non-Goals:**

- 不新增或删除配置字段。
- 不改变配置默认值、JSON 格式或即时保存位置预设的行为。
- 不引入新的 UI 框架或第三方依赖。
- 不重做设置项的输入校验、文案和视觉主题。

## Decisions

### 使用原生 TabControl 实现左侧导航

采用 WPF `TabControl`，将 `TabStripPlacement` 设置为 `Left`，为标签头设置固定或受约束的宽度，内容区域承载各组设置。这样可以复用现有窗口生命周期和命名控件，避免引入自定义导航状态。

备选方案是多个 `Expander` 或自定义按钮切换 `Grid` 可见性。前者仍会保留较长页面，后者需要维护选中状态、键盘行为和视觉样式，因此不采用。

### 按用途划分四个标签页

- “通用”：开机自启动、窗口置顶。
- “窗口位置”：窗口 X/Y、取当前、位置预设的新增/列表/跳转/删除/排序。
- “硬件监控”：硬件轮询间隔、CPU/GPU 温度上限、使用率颜色阈值、温度颜色阈值。
- “LED 灯效”：默认灯效模式、空闲恢复时间及说明文字。
- “关于”：当前程序版本、GitHub Releases 链接、作者 GitHub Profile、技术栈和开源组件信息、检查更新按钮。

此划分与现有页面标题和配置职责一致，不需要改变字段归属或模型结构。

### 使用程序集版本和 GitHub Releases API

当前版本 SHALL 从应用程序集的版本信息读取；发布配置应提供稳定的应用版本值，关于页不硬编码与构建产物无关的版本文本。项目 Release 链接固定为 `https://github.com/ChenDaqian/MagicCenterHub/releases/latest`，检查更新调用公开 API `https://api.github.com/repos/ChenDaqian/MagicCenterHub/releases/latest`，读取最新 Release 的 `tag_name`，去除常见的 `v` 前缀后进行版本比较。

更新检查使用 `HttpClient` 和现有 JSON 能力，不增加 NuGet 依赖；请求应设置合理超时和 GitHub API 所需的 User-Agent。API 被限流、返回无效版本或请求失败时，系统降级访问 `releases/latest`，从 GitHub 重定向地址或页面链接读取版本；两条路径都失败时才向用户提示检查失败，不打开错误链接。

### 更新结果处理

当远程版本高于当前版本时，提示用户发现新版本并打开 Release 页面；当版本相同或当前版本更新时，提示“当前已是最新版本，无需更新”。关于页的 Release 和作者 Profile 链接均使用系统默认浏览器打开。

### 保持保存与事件处理边界

布局移动不改变现有 `x:Name` 和 Click/DragDrop 事件绑定。`LoadValues()` 继续初始化所有控件，`SaveSettings()` 继续从所有标签页读取值并保存，应用和保存按钮仍位于标签页外的固定底部区域。

### 内容区域独立滚动

将 `ScrollViewer` 放在 `TabControl` 内容区域或每个内容页内部，底部操作区置于外层 Grid 的独立行。窗口高度可根据四个标签页中最长内容适度调整，但不改变不可调整大小的设置窗口特性。

## Risks / Trade-offs

- [标签头宽度不足导致文案截断] → 为左侧标签头设置稳定宽度，并在实际窗口尺寸下验证四个标签名称完整显示。
- [移动 XAML 后事件源或命名控件失效] → 保留现有 `x:Name` 和事件方法绑定，构建并执行关键交互验证。
- [用户在非当前标签页编辑后遗漏保存] → 保存逻辑仍集中读取全部命名控件，测试在多个标签页分别修改后点击应用/保存并检查配置结果。
- [最长标签页仍需要滚动] → 仅让内容区域滚动，底部应用/保存按钮和状态文本保持固定。
- [GitHub API 请求受网络、限流或版本格式影响] → 使用超时、User-Agent 和版本解析校验，并降级访问 `releases/latest`；两条路径都失败时明确提示检查失败，不影响设置窗口其他功能。
- [异步更新检查阻塞 UI] → 使用返回 `Task` 的异步事件处理，按钮检查期间禁用并在完成后恢复。

## Migration Plan

无需数据迁移。发布后现有 `settings.json` 可直接由同一 `Settings` 模型读取；如需回滚，仅恢复设置窗口 XAML/代码变更即可，配置文件不受影响。更新检查失败或不可用时，用户仍可通过关于页 Release 超链接手动访问发布页面。

## Open Questions

无。标签页名称、字段归属、仓库地址和作者主页已依据项目现有文档确定。
